# 开发路线

## 1. 项目目标

从原始 Socket 通信出发，逐步构建一个基于 Linux Reactor 模型、支持 C++20 协程与多线程协作的通用 TCP 网络库，最终通过 RPC 和实际服务验证其可复用性、正确性与性能。

按任务依赖与可验证成果推进，不将任务编号绑定开发天数。具体设计与验收要求在进入对应任务时确定。

## 2. Roadmap

### Phase 1：基础网络通信

目标：理解 TCP 网络通信，建立可靠的字节收发能力。

| 任务 | 内容 |
|---|---|
| N01 | TCP 连接建立与资源关闭 |
| N02 | Echo Server 与循环收发 |
| N03 | 部分读写、EOF 与异常处理 |

**阶段产物：** 正确完成 TCP 连接、数据收发与资源释放的客户端和服务端。

### Phase 2：事件驱动网络库

目标：从单连接通信演进为可复用的单 Reactor 网络库。

| 任务 | 内容 |
|---|---|
| N04 | 非阻塞 I/O 与 epoll |
| N05 | 网络资源与事件注册封装 |
| N06 | EventLoop、连接管理、任务投递与唤醒 |
| N07 | 网络缓冲区与背压控制 |
| N08 | 定时器与超时调度 |

**里程碑 M1：事件驱动 TCP 网络库**

能够管理多个客户端连接，具备明确的资源所有权、连接生命周期、事件调度、缓冲与定时任务处理能力。

### Phase 3：协程网络库

目标：在事件驱动架构上提供可等待的异步网络接口。

| 任务 | 内容 |
|---|---|
| N09 | C++20 Task 与协程生命周期 |
| N10 | 可等待的异步网络读写 |
| N11 | 超时、取消与完成竞争 |
| N12 | 任务组合与协程调度 |

**阶段产物：** 支持协程网络 I/O 的单 Reactor 网络库，并与回调式实现进行对比验证。

### Phase 4：多线程与并发架构

目标：引入后台任务处理与多线程网络调度能力。

| 任务 | 内容 |
|---|---|
| N13 | 工作线程池 |
| N14 | 跨线程任务回传、协程恢复与停机协调 |
| N15 | 多 Reactor 实验与完整安全停机 |

**里程碑 M2：并发协程网络库**

具备协程读写、超时取消、线程协作和安全停机能力。通过实验评估单 Reactor 与多 Reactor 的适用场景及性能差异。

### Phase 5：应用与工程验证

目标：验证网络库的通用性、稳定性与实际使用价值。

| 任务 | 内容 |
|---|---|
| N16 | 消息协议、序列化与 RPC |
| N17 | 实际服务应用 |
| N18 | 系统性性能评估 |
| N19 | 基于测量结果的性能优化 |
| N20 | API、文档、示例与阶段整理 |

**里程碑 M3：可复用 C++ 网络中间件**

通过 RPC 和实际服务验证公共网络接口，提供可复现的测试结果、性能报告及使用文档。

实际服务候选：内存 KV 服务或游戏房间服务器。

## 3. 工程要求

以下能力随项目演进逐步完善，不集中推迟到最终阶段：

- 资源所有权、生命周期与安全停机。
- 基础日志、自动化测试与 Sanitizer 检查。
- 关键架构节点的性能基线与对照实验。
- Git 版本管理与可复现的验收证据。
- 公共接口与业务实现的职责分离。

## 4. 可选扩展

以下内容不作为当前主线的必做任务，由实际需求与实验结果决定：

- HTTP / HTTPS
- 跨平台 I/O 后端
- 异步日志与可观测性系统
- 无锁数据结构与内存池
- 反向代理与负载均衡
- 分布式复制与一致性

## 5. 路线维护原则

- 整体规划优先修改、替换和删除，而不是持续追加。
- Roadmap 只描述目标、任务依赖和阶段成果。
- 当前任务的设计与验收记录在对应任务文件。
- 尚未进入的任务不提前确定详细接口、类结构或实现方案。
- 历史规划与源码演进由 Git 保存。
- 每个学习周从已完成任务中提炼至少一个有实现、实验或观察证据的技术成果。
