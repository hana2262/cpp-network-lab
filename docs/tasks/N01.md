# N01 建立一次 TCP 连接

状态：功能验收与本轮理解核验已通过，待人工审查，尚未提交或上传。本任务作为首次规范上传成果，后续任务沿用本页结构。

## 目标与范围

服务端监听 127.0.0.1:18080，等待一个客户端，accept 返回后打印监听 fd 与连接 fd，关闭两者并退出。客户端连接成功后打印“连接成功”，关闭连接并退出。

本项只建立连接，不发送应用数据。地址与端口是实验参数，先写在程序内，不提前建立配置框架。

## 代码入口与实现顺序

先完成 [server.cpp](../../exercises/n01-connect/server.cpp)，再完成 [client.cpp](../../exercises/n01-connect/client.cpp)。构建由 [CMakeLists.txt](../../CMakeLists.txt) 提供。

服务端：socket → bind → listen → accept → close。
客户端：socket → connect → close。

socket 取得通信端点；bind 设置本地地址；listen 将端点用于接受连接；accept 返回新的连接 fd；connect 发起连接；close 释放持有的 fd。监听 fd 不会被 accept 替换。

使用 IPv4、TCP、sockaddr_in，地址结构零初始化，端口使用 htons，地址转换可用 inet_pton。接口不熟悉时查对应 man 页面或请求最小用法提示，不要求盲猜。失败时报告操作与原因，释放已取得资源并失败退出。

## 构建与运行

在项目根目录：

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build -j2
```

先在一个终端运行：

```bash
./build/connect_server
```

再在同目录的另一个终端运行：

```bash
./build/connect_client
```

预期服务端先提示等待，随后打印两个不同的有效 fd；客户端打印“连接成功”；两者正常退出。fd 数值不固定。

## 设计解释

监听 socket 与已接入的连接分别持有 fd，分别关闭。listen 设置监听状态后返回；当前使用阻塞 socket，队列为空时 accept 等待连接，成功返回的连接 fd 可用于后续通信。本实验只建立连接，不收发应用数据。

地址与端口固定在程序内，暂不引入配置或资源封装。地址转换结果为 0 时直接报告文本无效；返回 -1 时用 perror 报告原因。后续操作失败时先报告原因，再关闭已经取得的 fd 并失败退出。
